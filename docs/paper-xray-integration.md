# paper-xray参考与精读落地

日期：2026-10-15。阅读 [上游SKILL.md](https://github.com/Wang-auspicious/paper-xray/blob/master/SKILL.md)、HTML说明与MIT许可。上游文档作为设计来源，未作为用户指令执行；没有安装全局技能、执行其脚本或建立跨项目个人画像。

## 借鉴与实现

| 上游思路 | 研舟中的实现 | 可核对的边界 |
| --- | --- | --- |
| 区分明确陈述、推断、猜测和未报告 | 四类证据标签，条目关联原文片段 | 模型的“原文有据”还需有逐字引文；核对通过不能证明解释正确。手动标签由作者判断 |
| 从失败场景理解机制 | 问题与洞见、机制与设定两条阅读路径 | 不自动判断作者意图或证明新颖性 |
| 公式先讲符号、形状、假设，再手算 | 公式与手算路径、本地KaTeX、辅助提示 | 不具备符号运算验证器；PDF提取公式可能失真，需对照原文件 |
| 症状→最低成本诊断→补丁代价 | 复现诊断条目，转为待验证研究设想并保留来源 | 转设想不会执行代码或把诊断标成实验结果；后续使用已有实验功能验证 |
| 明确记录读者是否理解 | 原文精确引文批注，重点/笔记/不懂/太长/已懂 | 划重点不算已懂；反馈按本篇和所选页范围发送给配置的模型 |
| 保留完整阅读过程 | 保存草稿、反馈、最近辅助读取页范围；导出MD/静态HTML/来源JSON | 单次超限直接提示缩小页范围；HTML是离线只读副本，公式保留源码 |

## 本项目的工作流贡献

精读发现疑问 → 保存诊断和原文定位 → 转为待验证研究设想 → 在现有总览配置对照实验 → 记录实际结果与作者判断 → 通过已有成果同步引用真实指标。

例如流程验证项目记录“先检查StandardScaler是否在训练集拟合，再做同种子对照”，解释标为推断，原文为示例资料的方法段，转设想时仍为待验证。这一流程让阅读产生可继续执行的研究记录。不能因此声称首次发明自动科研、证据追踪或统计方法，也没有测量学生效率提升。

## 界面设计

ui-ux-pro-max提供工具界面、角色配色与可访问性参考；其检索给出的Portfolio Grid不适合当前科研应用，未采用。taste-skill的适用范围排除应用和仪表盘，因此使用其字体、配色、真实内容原则，未套用营销站照片、英雄区或动效要求。工具和阅读布局同时参考本机Impeccable资料。

藏蓝文字与冷白表面承载长文；钴蓝表示操作与当前路径；绿/黄/红独立表示成功、提醒与错误。精读采用目录、正文、原文反馈三栏，平板反馈下移，手机改为纵向。正文15—16px，采用本地中文系统字体；KaTeX按需加载，不访问外部CDN。
