# 研舟 · 科研工作台

面向学生的本地科研工作台。四个功能共用项目、研究问题与文献库。

首页为研究总览：真实指标趋势、可筛选运行表格、所选运行的设置与日志。可在“研究设想”记录原文依据和作者判断，在“对照实验”执行有限次数的多种子比较。

GitHub参考、实际借鉴与参赛贡献说明见 [AutoResearch参考与本轮改进](docs/autoresearch-reference.md)。

## 本次实现

### 长文档、证据比较与研究任务

- PDF后台逐页解析，保留原文件、候选标题、文字坐标、图像区域和线框表格；扫描页用本机RapidOCR识别，显示置信度并提示对照原页。
- 每篇20MB、最多2000页；2个解析进程，单页90秒、总计20分钟、进程1GB、正文400万字符。超限或停止时保留已完成页，可继续解析；页面和引用按页加载。
- 从内容中的DOI/arXiv版本及文字相似度提示可能重复或修订的文献，两份原文均保留，不自动覆盖引用。
- 对每篇文献分别执行字符与词项双路稀疏检索，比较数据、种子、硬件等设置。无模型时只展示候选原文；配置模型后要求逐字引文，无法核对的提取值不作为有依据的值显示。
- 研究任务支持实际Function Calling，最多6次工具调用，保存参数、实际返回和失败信息；模型可检索、比较和整理复现条件，不执行外部实验。无模型时明确执行固定本地流程。
- 比较表可导出CSV，工具记录可导出JSON；结果可保存为待验证设想，重复点击不会重复建档。
- 标题和双栏识别是启发式候选；公式候选未转为可信LaTeX，扫描图表未还原为结构化数据。引文存在不代表解释正确；本次未找到不代表全文未报告。尚未实现稠密向量检索、双语对照阅读和引文网络。

验证范围与分阶段发布方式见 [本阶段记录](docs/structured-research.md)。

### 研究总览、设想与对照

- 真实曲线按提交顺序显示，按数据来源与任务分开选择；点击图点或运行名称查看设定、日志与文件。
- 保存研究设想、可检验预期、原文片段、关联运行、作者判断与下一步，导出Markdown和来源JSON。
- 对照实验支持内置Iris的标准化与C单因素变化。每个方案使用同一组2至5个种子，最多4个方案，逐次真实执行。
- 展示有效数、accuracy均值、样本标准差和同种子配对差值。停止后未执行的队列不继续启动，已完成结果保留。
- 选择研究设想启动对照时，运行记录自动关联；判断仍由作者填写。可从记录看到已引用相关运行的成果稿及同步状态。

### 实验复现

- 新建与切换项目，保存研究问题。
- 用已导入文献整理执行计划；配置模型后，可辅助分析资料和仓库文件。
- 内置Iris分类案例：真实执行逻辑回归，支持关闭标准化、修改C、数据划分、种子与迭代次数。
- 导入公开GitHub仓库或ZIP，查看README、依赖文件与Python入口。
- 外部仓库在Docker中执行；限制CPU、内存与进程数，仓库只读、运行时无网络，只允许写入成果目录。
- 保存真实日志、状态、参数、指标与成果文件；支持停止、失败分析、运行比较。
- 导出复现材料ZIP，包含说明、运行配置、原始日志、图表、预测记录、示例复跑代码和项目仓库。

### 文献与开题

- 导入PDF、UTF-8 TXT与Markdown，保留原文、页码及片段定位。
- Crossref检索真实题录、作者和DOI；题录不会作为全文证据。
- 生成方法、数据、指标、局限比较条目，支持作者修订与核对，导出CSV。
- 基于项目全文检索证据。配置模型后可辅助综合；无有效引用的模型说明不作为有依据的回答显示。
- 点击引用回看原文，导出带来源定位的开题准备材料。

### 成果同步

- 编辑Markdown成果稿，用 `{{mean_score}}` 等变量引用本项目成功运行的真实指标，设置小数位或百分比格式。
- 选择实验或分析记录生成指标比较图，保留数值、来源、运行参数与生成版本。
- 保存草稿后提示来源和数值变化；点击“生成并同步”更新正文、图表与来源记录。
- 导出Markdown正文、指标CSV、PNG图表与来源JSON的成果ZIP。生成前的草稿与上次生成的成果分别标明状态。

### 数据分析

- 上传CSV、TSV或XLSX，查看字段类型、缺失、重复行与原始数据预览；也可从实验运行导入CSV/TSV成果。
- 选择数值字段，设置完全重复行去除、保留缺失／删除缺失行／中位数填补、单位换算与范围筛选。
- 实际计算描述统计、分组描述比较和Pearson相关，生成表格与图表，记录处理顺序、有效样本量和日志。
- 保存分析记录，载入历史处理计划继续运行；导出原始输入、配置、独立Python代码、环境说明和结果，支持独立复跑。
- 两个新模块无需配置模型服务。人工示例仅用于体验流程，界面明确标注其来源。

## 推荐体验顺序

新增流程：在总览新建研究设想，关联文献与开题已有的原文片段，保存后到“对照实验”选择该设想并开始。核对逐种子差值与原始运行后，再记录作者判断；到成果同步绑定需要写入成果的实际指标。

1. 新建项目，写下“特征标准化是否改变Iris分类结果？”等明确问题。
2. 载入示例说明，或在文献与开题上传自己的论文全文。
3. 在文献与开题整理比较条目、查看原文，并修订需要确认的信息。
4. 在实验复现运行默认配置，再关闭标准化运行一次；在运行记录勾选两次实验比较。
5. 下载真实图表、预测文件与复现材料；示例材料不会宣称复现了已发表论文。
6. 在数据分析上传数据或载入流程示例，选择处理规则并执行；查看统计、分组与相关结果，下载复跑包。
7. 在成果同步添加指标引用，编写含变量的正文并生成成果。改选另一次运行、保存草稿，查看变化提示，再生成更新后的成果。

成果同步正文示例：添加名为 `mean_score` 的指标引用，选择某次分析的 `mean:score`，正文写“平均得分为 {{mean_score}}”。变量只替换已有真实数值，研究解释与结论由作者撰写。

## 模型服务

设置页可配置兼容Chat Completions的服务地址（包含 `/v1` 等提供方要求的路径）、模型名称、密钥，并测试连接。

- 密钥保存在本机 `data/model.json`，设置查询不返回密钥；`data/`已排除出Git。
- 保存配置后，对所选文献片段或实验日志的模型分析会发送给配置的服务。
- 可用 `RESEARCH_MODEL_URL`、`RESEARCH_MODEL_NAME`、`RESEARCH_MODEL_KEY` 环境变量提供默认值。
- 当前未提供真实服务凭据。无模型仍能导入文献、检索原文、生成明确标注的规则条目和运行实验；不能把规则提取称为模型理解。

## 外部仓库运行

启动Docker Desktop，然后在设置页“准备隔离运行环境”，或手动执行：

```powershell
docker build -t research-workbench:0.1 -f Dockerfile.runner .
```

当前镜像已经构建。默认依赖包括numpy、scikit-learn与matplotlib。仓库需要其他依赖时，修改 `Dockerfile.runner` 后重新构建；首版不自动安装或修改外部仓库依赖。

程序选择仓库中的Python入口，每行填写一个参数。仓库挂载为 `/workspace`，成果目录为 `/output`；程序可读取 `RESEARCH_OUTPUT` 环境变量取得成果目录。

`examples/iris-repository.zip` 提供了可直接上传的完整隔离分类示例，入口选择 `train.py` 并填写下列参数。

示例参数：

```text
--config
/output/config.json
--output
/output
```

记录指标时写入 `/output/metrics.json`，格式为数值字典，例如 `{"accuracy": 0.91}`。工作台仅显示实际写出的有限数值，不补写缺失结果。

运行不联网，需将所需数据一并放入仓库压缩包，或在代码中使用镜像已有的内置数据。GPU、交互式Notebook、自动修复与任意依赖自动部署不属于首版已实现能力。

## 验证与边界

```powershell
New-Item -ItemType Directory -Force tmp
.\.venv\Scripts\python.exe -m pytest tests -q --basetemp tmp/pytest
node tests/browser-smoke.cjs
node tests/browser-studio.cjs
```

浏览器验证脚本使用本机Chrome，服务须先启动；会创建名称明确的流程示例项目，真实执行实验和数据分析，并验证成果更新。截图与报告保存在 `tmp/ui/`。

- 已覆盖真实本地实验、Docker仓库成功/失败、引用与导出、跨项目边界、不安全ZIP路径、未知模型引用丢弃。
- 新模块覆盖已知数据的统计值、去重、填补、换算、筛选、常量字段相关、Excel/TSV输入、跨项目来源隔离、成果版本更新和导出代码独立复跑；桌面与手机检查覆盖真实操作及页面溢出。
- 内置案例是本项目编写的流程示例。完成小规模运行不意味着完成某篇论文的全部复现。
- 模型只能协助整理，学生需核对研究设定与结论。首版不自动证明新颖性、统计显著性或生成完整论文。
- 扫描版PDF需先进行OCR；单篇文献最大20MB、300页，仓库ZIP最大25MB、解压后100MB。
- 数据表最大10MB、100000行、100列，第一行为不重复的字段名。CSV/TSV支持UTF-8与GB18030；XLSX读取第一张表，公式须先转为数值。每次最多分析12个数值字段，分组字段最多200个不同值，分组图展示前15组，完整结果保留在CSV中。
- 数据分析当前提供描述统计与Pearson相关，不能据此自动断言因果或显著性。成果同步当前使用Markdown正文，不提供Word模板排版或自动撰写研究结论。
- 自动多种子对照当前支持内置Iris，外部仓库继续使用已有Docker运行入口。重复随机划分可能重叠，样本标准差和配对均值不是显著性检验。最多20次运行，每次有独立时限；没有自动修改代码或无人值守生成论文。
- 该服务仅绑定本机回环地址，尚未实现面向公网的账号系统。不要直接改为公网部署。
- 数据、运行和模型设置位于 `data/`。源代码版本、记录主键和普通配置用于管理，没有新增hash、冻结contract、baseline或发布gate。

## 使用的开源资源

### 论文精读与当前界面

文献与开题 → 论文精读：从文献库点击“精读”，按问题、机制、公式、实验、诊断和局限组织笔记。每条记录区分原文有据、推断、猜测和本次材料未找到；可关联原文片段、编辑、移除并撤销。公式在本地通过KaTeX排版。

原文支持按段批注，也可选择文字后批注；“重点”不自动算“已懂”。反馈类型包括重点、笔记、不懂、太长、已懂。复现诊断可以转为待验证的研究设想，带上来源与诊断方案，继续使用总览中的实验流程。重复点击不会重复创建同一设想。

配置模型后，可按页范围和明确反馈追加精读草稿。单次原文最多60000字符，批注最多20000字符，超过时提示缩小范围；不会静默截断。系统校验来源编号和逐字引文，不合格的“原文有据”降为猜测，但这不能证明模型的解释正确。每篇最多40条精读笔记、200条批注。模型未配置时，手动精读、批注、转设想和导出仍可使用。

精读包包含Markdown、可离线阅读的静态HTML和原文来源JSON；HTML包为只读，公式保留LaTeX源码。新上传的PDF/文本/Markdown同时保留原文件，旧文献仍可查看已提取文字，但无法自动找回此前未保存的原文件。系统未增加图像理解或OCR。

配色统一为藏蓝文字、钴蓝操作色、冷白阅读面，成功/警告/失败采用独立语义色。桌面精读区采用目录、正文、原文反馈三栏，较窄屏幕将反馈移到正文下方，手机目录和操作改为纵向排布。

设计参考了ui-ux-pro-max的工具界面与可访问性建议、taste-skill的字体/配色/真实内容原则，以及Impeccable的工具阅读布局。taste-skill本身排除仪表盘和应用界面，本项目没有套用它面向营销站的照片、英雄区或动效流程。

精读思路参考 [paper-xray](https://github.com/Wang-auspicious/paper-xray)，许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。借鉴点是证据分层、机制拆解、手算、复现诊断与明确理解反馈；本项目的贡献是将这些阅读记录连接到已有研究设想、实际实验和成果引用流程。尚未通过用户研究证明节省时间或提高科研质量。

本项目独立实现业务流程，未复制此前农业项目，也未把OpenHands、Paper2Code或PaperQA的源码作为底座。

- React / Vite：前端框架与构建。
- Lucide：图标。
- KaTeX：本地公式排版，禁止可信HTML扩展，不依赖外部CDN。
- FastAPI / Uvicorn / python-multipart：本地接口、服务与上传。
- pypdf：文字提取。
- scikit-learn：Iris数据、分类、指标与TF-IDF原文检索。
- numpy / matplotlib：数值计算与实验、分析图表。
- openpyxl：XLSX数据读取。
- httpx：配置模型、Crossref和GitHub服务请求。
- Docker Python镜像：外部实验运行环境。

第三方组件的版权及许可证以安装版本为准。参赛说明应将上游组件能力与本项目的流程、交互和实现贡献区分。参考来源：
